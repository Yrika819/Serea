**Status:** active synthetic-only experiment; architecture and production enablement are not authorized.

## Goal and boundaries

Compare (C1) extraction of the pure P6 evaluator so the real active Policy snapshot can be read and evaluated while Storage holds its SQLite write transaction, and (C2) an experimental authority-owning crate/private module whose external Cargo surface cannot forge a commit result or Permit. A Host-private coordinator may use one concrete Fake Provider instance only. All DBs and effect ledgers are disposable synthetic fixtures. No production Provider, credentials, Production Memory, canonical migration 0009/0010, Receipt, retry, external effect, main/PR mutation, or formal architecture adoption is allowed.

The threat model covers untrusted API inputs and arbitrary downstream Cargo consumers of public crate APIs. Rust privacy does not protect against arbitrary code in the same process, executable/database tampering, or physical power loss. Success of typed grant use, Event append, a policy explanation, Provider ID, or a caller-provided readiness value is never itself an authorization proof.

## Stops and acceptance

- Stop any design that needs `unsafe`, a caller `authorized`/`ready` boolean, a caller-built CommitProof, a public unchecked Intent writer, a default/release synthetic feature, a canonical migration, or real Provider I/O.
- C1 counts only if exact rules/revision are read under the same `BEGIN IMMEDIATE` as the experimental decision/commit; no rule duplication and no policy/storage cycle.
- C2 counts only if the externally compiled real-crate consumer cannot construct/clone/serialize a Permit or mint committed proof, and public bypasses are explicitly enumerated. A negative import alone is not evidence about a type that does not exist.
- Host linkage counts only if Permit issuance follows actual successful commit and the same Host-owned instance is pinned/rechecked; process death after commit cannot restore a Permit.
- RED/GREEN must use an isolated mutation and restore all changes. Real SQLite, two connections, rollback/reopen and fault boundaries are distinct evidence.
- Final status is exactly one of `C1_C2_PROOF_CONFIRMED_SYNTHETIC_ONLY`, `C1_C2_PROOF_PARTIAL`, `C1_C2_PROOF_REFUTED`, `C1_C2_PROOF_NOT_RUN`.
