## Diagnostic design and limitations

The non-required workflow uses a disposable no-real-account emulator; it does not change the Required Gate. It records bounded main/system/crash/events logcat, UTP/JUnit and Gradle output, concurrent device and host snapshots, process IDs, exit-info, ADB and reader state, memory/cgroup counters and time boundaries. Raw emulator logs are retained for 14 days. Logcat, the live monitor, and Gradle output each have a 16 MiB file limit; reaching a limit makes diagnostic evidence incomplete. Each snapshot records command exit and output size; the first 16,000 bytes of selected output are retained. Truncation, sampling intervals, unsupported commands, post-UTP uninstall and missing cgroup data constrain interpretation. Test result and diagnostic evidence completeness are separate; incomplete required evidence fails the diagnostic workflow.

Android 15 does not implement `dumpsys activity instrumentation` as an activity subcommand and can return exit 0 with an error message. The replacement queries `dumpsys activity processes`: Android 15 AOSP's [ProcessList.dumpProcessesLSP](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android15-release/services/core/java/com/android/server/am/ProcessList.java) calls `dumpActiveInstruments`; [ActivityManagerService](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android15-release/services/core/java/com/android/server/am/ActivityManagerService.java) emits `Active instrumentation:` only when active. A missing active snapshot is incomplete, not proof of absence. Run 41929792936 captured the target runner as active, while identifying focus and cgroup observation gaps; the follow-up switches to `dumpsys window` and searches the runner membership cgroup as well as the root. The follow-up still requires emulator validation.

Earlier dispatch 41862998038 was cancelled while queued because review found its package-absence check would reject normal Android 15 behavior; it is not a test result. After baseline, change one hypothesis at a time and preserve assertions and IME/InputConnection checks. Formal API 26/35 and all required checks remain necessary for any evidence-backed fix.

## Source modes

Pull-request diagnostics and dispatch `baseline` mode retain the historical Android-tree check against `334da4bf8855e1b7fefc019a3b397aff506c9913`; for a pull request, the explicitly recorded PR base must descend from the historical baseline, and both its Android tree and the checked-out Android tree must match the historical tree. A documentation-only main update therefore preserves reproducibility; an Android tree change deliberately fails this precondition. To diagnose a different trusted same-repository source, explicitly dispatch `candidate` mode on a ref that contains this workflow and enter that selected ref's full 40-character commit SHA. The checked-out commit must equal the input exactly. Candidate mode requires the test harness and disposable-emulator guard files to match pinned blob hashes from trusted harness `2c4327399e5adfec8e106df50a5c5bc6e11c50b8`; this does not require that commit to remain reachable. If they evolve, the trusted pins require a reviewed update. An arbitrary PR branch that lacks this workflow needs a dedicated validation commit and cannot be selected directly. The workflow uses read-only repository permissions and no secrets. No untrusted fork PR is executed by the diagnostic job.

Every run records mode, immutable source SHA, Android tree, historical baseline tree, harness reference SHA and its match status, GitHub event SHA, run ID and attempt. The test evidence additionally records actual APK hashes. Candidate diagnostics do not establish historical-baseline reproduction or satisfy the formal Required Gate. Pull-request workflow definitions can themselves be changed by an author; job-level checks are a defense in depth, not a substitute for repository policy.

The historical PASS on PR HEAD `2c43273` applies to that candidate and its merge result, not to main: main `334da4b` still has the prior failed Required run. The past instrumentation termination remains unexplained.
