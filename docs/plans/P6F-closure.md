## Scope and threat model

P6F reviews the P6B durable policy and approval authority, P6C deterministic policy, P6D authenticated approval lifecycle, and P6E TaskEngine/Scheduler orchestration against a local attacker who can supply malformed or stale API inputs, replay messages, race independent SQLite connections, interrupt a process, or reopen persisted state. The review asks whether those paths can mint or widen authority, corrupt the durable record, revive cancelled work, bypass current Policy, expose protected values, or cross the P6/P8 boundary.

This is a source-and-test audit backed by hosted CI. It is not a formal proof, exhaustive state-space exploration, hostile filesystem test, or proof of physical power-loss durability. A passing test establishes only the case it exercises.

## Residual risks, limits, and P8 obligations

- A malicious process with write access to the SQLite database file can bypass application trust assumptions or damage the database. P6 detects several malformed states but does not provide tamper-proof storage.
- Software fault injection and process termination do not prove physical power-loss behavior, storage-controller guarantees, or filesystem durability.
- Host-authenticator correctness, secure UI/device/session binding, local-admin controls, key custody, and clock quality remain host integration responsibilities.
- P6 never guarantees exactly-once external effects. P8 must define and implement durable dispatch intent, provider idempotency/reconciliation, `RequestId` minting, and atomic Grant-use consumption joined to dispatch intent; it must revalidate current Task/Step/Plan, Policy revision, capability overlay, registry generation, descriptor digest, canonical args, expiry, cancellation, and revocation immediately before dispatch.
- P8 must handle ambiguous provider outcomes, retries, result persistence, credentials and secret exposure under the credential-store contract, and prove that no stale P6 evidence alone can authorize dispatch.
- No provider invocation, external dispatch, P8 implementation, release, main integration, or exactly-once claim is part of this closure.

**Closure verdict:** P6F adversarial evidence is complete for the reviewed source and listed test/CI scope. No unresolved P6 authority blocker was found. Design-only assumptions and P8 obligations remain as stated. `P6F_VERIFIED_ON_UNMERGED_BRANCH`.
