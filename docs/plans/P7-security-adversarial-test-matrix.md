**状態:** RED-first future regression plan。新しいtestや実装はこの文書では追加しない。
**試験データ:** synthetic fixtureのみ。production device/account/database/credentialは使用しない。

## RED-first deterministic test catalogue

All tests use an ephemeral temporary SQLite DB, synthetic clock, generated IDs, fake provider/model strings and controlled backup copies. Tests assert both returned result and durable database state after reopen. Each test must begin RED against the proposed unsafe behavior and become GREEN only when an approved implementation enforces the invariant.

| Test ID | Adversarial setup | Expected durable result / invariant |
| --- | --- | --- |
| `p7_owner_cross_read_write_delete` | Owner A owns synthetic Task/Memory; Owner B guesses IDs and issues search/update/forget. | Zero rows/results from B; no FTS or tombstone mutation; generic deny; Owner A state unchanged. |
| `p7_owner_spoofed_request` | Model JSON, source provenance and caller each claim a different OwnerId than host authentication. | Host-derived owner wins or request is rejected before insert; no Task binding/Memory row/Blob reference. |

### Evidence that needs a later target

- **Actual Rust SQLite:** run `rusqlite` bundled build feature probe, FTS5 create/search/rollback/rebuild/integrity, actual migrations, FK/UNIQUE/trigger behavior, WAL recovery and multi-connection concurrency on supported Linux, macOS Intel, macOS arm64 and any selected Android runtime. Python SQLite results are not substitutes.
- **Japanese retrieval quality:** representative licensed or synthetic Japanese corpus, relevance judgments, stable tokenizer/version, query-set and owner-approved acceptance metric. Until then report limitations, not a quality score.
- **Isolated real-device tests after separate authorization:** Android Keystore, biometric freshness, manifest/export and OS permission behavior may only be validated on an isolated emulator or specifically authorized test device with synthetic data and no production account. No such access is authorized by this plan.
- **Provider and GoalLatch:** isolated fake-only contract tests first. Real account/service/device integration requires a later separate authorization after its production gates; never use actual private data or credentials for these tests.

Tests can prove only the specific implementation and test environment examined. They do not prove secure erase of SSD/WAL/backups, protection against a compromised host OS, provider correctness, universal Japanese quality, or production authorization.
