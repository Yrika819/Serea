# Isolated llama.cpp Android feasibility PoC

This is a standalone test application under `tools/`. It is not included by the Serea Android Gradle settings, product APK, normal chat composition, or any existing CI gate. The target APK requests no permissions. The generated AndroidTest APK inspected in API 26 run `40589226410` requested only `android.permission.REORDER_TASKS`; it did not request `android.permission.INTERNET`. The test code performs no network I/O. The host runner fetches the pinned model fixture, then installs it locally before instrumentation. It uses no real credentials or service accounts.

The Kotlin adapter has the same suspend `send(request): response` shape as Serea's `ModelChatPort`, but is a test-local structural contract; it does not import or replace the production interface. The adapter verifies the model's SHA-256 before passing a path to JNI. Its native runtime is pinned to llama.cpp commit `276378515ceebee5d14bcc8536603dd5c87491a2` (tag `b11927`).

## Fixed model candidate

The test fixture is the official `ggml-org/SmolLM2-135M-GGUF` repository at revision `1076b85d135017971845b19b8d07df1479155988`. The repo metadata declares `apache-2.0`; its model card identifies `HuggingFaceTB/SmolLM2-135M` as the base model. The selected Q4_K_M file is 101,016,128 bytes with SHA-256 `e3131339bf4e8065265593d4fd8f7bb7ff2d3abff1edb5618aa1197b89cad9f5`.

The weight file is deliberately absent from this repository. Before an explicitly selected disposable Emulator run, the workflow fetches only the small metadata response for this exact repository revision and verifies its immutable SHA, declared `apache-2.0` license, and base model; it does not download model weights during this step. The inference step later fetches only this exact file, checks both size and SHA-256, stages it to app-private Emulator storage, and passes the same SHA as an instrumentation argument. The instrumentation test fails if either argument or the model file is missing; it does not skip inference. The test runner removes and verifies the app-private copy when the target package remains installed and removes/verifies the temporary copy. If the instrumentation runner already uninstalled the target APK, direct app-private deletion is recorded as not individually verified; the fresh AVD is not reused, is wiped on creation, and is discarded with the ephemeral GitHub-hosted job VM. The workflow uploads evidence only, never model weights.

## Diagnostic workflow boundary

The non-required `.github/workflows/g3-ondevice-poc.yml` accepts an explicit `workflow_dispatch` choice of API 26 or 35. Its push path remains gated by `[g3-poc-run]` and requires exactly one API marker, `[g3-api=26]` or `[g3-api=35]`. A host regression rejects both markers, repeated markers, or no marker before SDK setup, Emulator creation, or model download. This lets a draft-branch diagnostic select one API without rerunning the other. The workflow records the complete installed SDK package list and explicit SDK, build-tools, NDK, CMake, Emulator, and selected system-image revisions; it also records KVM/acceleration metadata. SDK package names are selected in workflow source, while the exact resolved package revisions are retained as run evidence and may change over time. It captures pinned model license metadata without fetching weights, runs the synthetic download-bound check, and builds both APKs before creating an Emulator or downloading model weights. It uses the matching `google_apis;x86_64` system image and refuses to continue without hardware acceleration. The target APK permission allowlist is empty; the AndroidTest APK allowlist contains only `android.permission.REORDER_TASKS`. Both generated APK manifests are checked against those exact allowlists. The diagnostic installs and hash-checks both APKs, fetches the exact bounded model fixture, stages it app-private, and invokes one exact non-skipped test. The fresh AVD is created with `-wipe-data` and discarded with its ephemeral GitHub-hosted job VM after artifact capture. This diagnostic remains separate from product Chat and all Required gates. Since this workflow is currently on an unmerged G3 Draft branch, the immediate API 26 run uses the marked-push route; GitHub manual dispatch is available when the workflow exists on the default branch.

Both Gradle invocations run through `run_poc_gradle`, which changes to this standalone project directory before executing `./gradlew`. The pre-build `scripts/test-gradle-project-dir.py` regression check verifies both call sites, the instrumentation target-context API, and the `Long` PSS counters. Guest CPU pressure is optional: access denial is recorded and does not stop the diagnostic. The global EXIT cleanup records the primary status, removes any partial host/device model, and resets shared cleanup state. `scripts/test-runner-failure-paths.py` uses fake `adb` to test denied PSI and early-exit cleanup. These guards follow failures in runs `40510213740`, `40511062977`, and `40512775686`.

## Native ownership and lifecycle contract

The llama.cpp JNI resources are process-global in this PoC, so `NativeLlamaEngine` enforces one active engine lease per process. A second engine cannot load while another owns the model; only the matching engine ID may generate, cancel its `(engineId, generationId)` request, or free the native state. Closing releases the lease, after which a new engine may load. Per-engine single-thread executors serialize load, generation, and close. A load queued before `close()` checks lifecycle state before native entry and completes with an error when close wins. This is an explicit PoC singleton contract, not a product concurrency design.

The instrumentation source contains deterministic checks for second-engine rejection, same-numbered cross-engine cancel/free isolation, successful reuse after close, queued-load versus close (with a 15-second bounded await), queued cancellation, a test-only barrier inside llama.cpp's installed abort callback, close-state rejection, and hash-matched corrupt GGUF rejection. The cancellation case waits until that callback is entered during `llama_decode`, cancels while the callback is held, releases it, and asserts that the callback observes the cancelled request. This source-level test is **not yet Emulator-verified at the current revision**; in-compute abort-callback cancellation remains **NOT_VERIFIED** until an API Emulator run executes it. Earlier Emulator evidence exercised cancellation at the pre-decode `onNativeGenerationStart` gate only and did not verify the abort callback during computation. An expected close rejection is converted to a value inside its async child so it cannot cancel the test parent; cancellation and unexpected failures remain failures. The instrumentation logs process PSS as an observational metric before/load/after generation/after close; PSS is not asserted as proof that native memory was returned to the OS.
